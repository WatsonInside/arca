# Arca · DESIGN.md

界面契约。改动 UI 之前先读这一页；`scripts/design_audit.py` 会把这里能机器检查的
部分跑一遍（退出码 2 表示有违规）。

设计语言来自四处参考的提炼，取舍按「这是桌面压缩工具」来定，不是照搬网页落地页：

- **impeccable**（pbakaus）：反套路清单与「确定性检测优先」——规则要能被脚本验证，
  不能只靠手感；同时它主张把产品事实（PRODUCT）与视觉系统（DESIGN）分开记录。
- **emilkowalski/skills**：动效的全部硬规则（缓动、时长、可动画属性、按压值、
  频率决策），来自作者在 Vercel / Linear 的经验。
- **ui-ux-pro-max**：对比度、焦点可见、长文本重排、坏数据边界等交付前清单。
- **qt-material-widgets**：Material 的反馈传统——按压/切换要有可感知的物理反馈，
  而不是只有颜色变化。

## 1. 颜色

令牌在 `styles.css` 的 `:root` / `[data-theme="dark"]`。**只用令牌，不写裸色值。**

| 用途 | 令牌 | 约束 |
| --- | --- | --- |
| 正文 | `--ink` | 近黑但带蓝相（`#15171c`），不用纯黑 |
| 次要文本 | `--ink-2` | ≥ 6:1 |
| 提示/说明 | `--ink-3` | **≥ 4.5:1**（11px 小字也在用，不允许「好看的浅灰」） |
| 占位/禁用 | `--ink-4` | 仅非必要信息，不可承载语义 |
| 强调 | `--accent` | 每屏只有一个强调色；不叠加第二主色 |
| 语义 | `--ok` / `--warn` / `--err` | 永远配图标或文案，**不靠颜色单独传意** |

- 深浅两套都必须独立校验对比度，不靠「深色模式看起来还行」。
- 禁止纯黑/纯灰（要带色相）、禁止紫蓝渐变当主视觉、禁止发光当主affordance。
- 背景的两层径向光是氛围，不是内容；不要在它上面放低对比文字。

## 2. 排版

- 系统字体栈（macOS 原生感），中文回落 PingFang SC。
- **三档正文 + 元数据**：13（正文、行标题、控件标签）/ 12（说明、次要信息）/ 11（元数据、
  徽标、计数）。展示级只有 15 / 15.5（区块标题）、22 / 23（页面标题与版本号）。
  允许的中间档：12.5（分段控件按钮、路径 pill、动作条）、11.5（极小徽标）、10.5（角标）。
  低一档只能用于**不需要连续阅读**的内容——把「要读才知道后果」的句子放在 11px 是错误。
- 说明文字（`.opt-hint`、`.opt-note`）行高 1.5–1.6；13px 正文配 18px 行高。
- **正文不随窗口缩放**（px 不是 rem）：字号是设计决策，不是浏览器设置。
- 数字一律 `font-variant-numeric: tabular-nums`（大小、进度、百分比、计数）。
- 标题 `text-wrap: balance`，正文 `text-wrap: pretty`。
- 尖括号包裹的路径/文件名必须能重排：`min-width: 0` + `overflow-wrap: anywhere`；
  列表行内用单行省略号，工具提示不依赖 hover 才能看全。

## 3. 图标

全部是 24 单位画布的描边图标（`<symbol>` + `<use>`），一个几何来源、一套光学规则。

| 规则 | 值 | 理由 |
| --- | --- | --- |
| 线宽来源 | **只在 CSS**：`svg { stroke-width: 1.8 }` | 画在 `<symbol>` 上的表现属性优先级高于继承，写在图形里就没法按尺寸补偿 |
| 基础线宽 | 1.8（简单几何字形 2.2） | 30 个图标原来有 1.6/1.7/1.8/1.9/2.1/2.2/2.4 七档，相邻图标能差 20% |
| 光学包围盒 | 14–20 单位（24 网格） | 11 单位的「停止」在任务卡里比周围小一圈；22 单位的齿轮顶到画布边缘 |
| 显示尺寸 | 11 / 13 / 14 / 16 / 22 / 30 / 44 | 原来是 12/13/14/15/16/17 混用，`design_audit` 会拦下新尺寸 |
| 小图标补偿 | 11–14px 用 2.0–2.5 源线宽 | 24 → 13px 缩放后 1.8 只剩 0.98px，会断线 |
| 大图标补偿 | 22px 1.5、30px 1.45、44px 1.15 | 大尺寸下同样的 1.8 会显得比正文还粗 |
| 对齐 | 网格居中（`place-items: center`），不手调 | 图标的视觉中心与描边中心不同，手调会把下一处改坏 |

不要为某个尺寸复制一个新 symbol（原来的 `i-layers-sm` 就是这么来的）；尺寸差异交给 CSS 的线宽补偿。

**成对图标共享底形**：压缩 / 解压是同一只「带盖的箱子」，只有箭头方向相反。判断标准是
「把标签遮住，用户能否把两个图标配成一对」；能做到的配对不需要文字解释，做不到的（例如
层叠 vs 下载托盘）再多文案也只是补救。注意避开平台已有语义：浅托盘 + 向上箭头 = 分享，
所以这里必须画出箱盖。

**品牌标记不使用自绘图形**：侧栏 30px 的品牌位显示 `app-icon.png`（由 `assets/Arca-1024.png`
降采样而来），也就是 Dock / Finder / DMG 上那张图标本身。以前这里画的是 `i-layers`
（三层图层），和应用图标（带拉链的卡片）完全是两套图形——同一品牌在两个位置长得不一样。
任何"再画一个近似 logo"的做法都会随时间漂移，所以直接复用位图。

## 4. 动效

**缓动**（`--ease-out` / `--ease-in-out` / `--ease-panel`）：

| 场景 | 曲线 |
| --- | --- |
| 进入/退出、hover、按压、菜单 | `--ease-out` `cubic-bezier(.23,1,.32,1)` |
| 屏幕上位移/形变（分段控件滑块、展开箭头） | `--ease-in-out` `cubic-bezier(.77,0,.175,1)` |
| 抽屉式面板（设置面板） | `--ease-panel` `cubic-bezier(.32,.72,0,1)` |
| 持续运动（进度条 indeterminate） | `linear` |

**时长**：按压 120ms · hover/小控件 160ms · 菜单 132ms · 行进入 220ms ·
面板 300ms。**交互反馈一律 ≤ 300ms**，超出的只允许留白类动画。

**硬规则**

1. 只对 `transform` / `opacity` 做动画；`width` 仅分段控件滑块一处例外（已注明）。
2. 不进 `scale(0)`：进入态最小 `scale(0.955)` + `opacity: 0`（菜单即如此）。
3. 不用 `ease-in` 做 UI 动画；不用 `transition: all`。
4. 弹层 `transform-origin` 跟随触发点（菜单贴边翻转已在 `menu.js` 实现）。
5. 频繁动作不做动画：**⌘1/⌘2/⌘3 切页无动画**（`setView(..., {instant:true})`），
   每周用几百次的动作，动画只会读成卡顿。
6. 按压反馈统一 `scale(0.94–0.99)`，主按钮同时收阴影（按下 = 靠近纸面）。
7. 开关拨钮按下变宽（18px）再回弹，替代整体缩放——Material 的经典手感。
8. `prefers-reduced-motion`：保留透明度/颜色过渡（120ms），去掉位移与缩放，
   **不是把一切压成 0.001s**。

## 5. 侧栏

- 宽度固定 208px（内容区 180）。导航只有三项，**不要靠加宽侧栏来「显得充实」**。
- 结构是「顶部：品牌 + 导航」+「底部簇：最近任务 / 引擎卡 / 设置」。底部簇由
  `margin-top: auto` 推到底，空白落在导航与簇之间——读作间隔，而不是半屏没做完。
  窗口越高空白越大，这是可接受的；把它均分成多段留白才是错。
- 「最近任务」最多 3 条，只收已结束的任务（完成 / 失败 / 已取消），最新在前；
  条目名去掉「压缩 / 解压 / 校验」动词（图标已经表达了动作），把宽度留给文件名；
  点击切到任务页并高亮那条任务。空列表时整块隐藏，不占位。
- 侧栏的状态必须由轮询驱动，而不是「切到任务页时才刷新」——否则压缩时侧栏是死的。
- 落款（`Watson inside`）是底部簇的最后一项，排在「设置」之后：11px / `--ink-3`，
  与说明文字同档；左边距对齐导航项，hover 才升到 `--ink` 并浮出浅底。署名只出现这
  一处——设置页页脚仍然只有 `v1.0.0`，同一事实不说第二遍。
- 侧栏里的外链一律 `preventDefault` 后走 `native('openUrl')`：webview 一旦跟着导航
  走，就没有返回键，等于把 App 换成了网页。

## 6. 设置的层级

设置面板是「一屏能看完」的东西，不是功能清单。规则：

- **默认状态不滚动**（`menu_test` 有断言）。需要滚动才能看到「设为默认」，说明层级错了。
- **同一事实只说一次**：三个组件的版本原来在「引擎」和「关于」各印一遍，现在合并成
  `版本` 一行，页脚只留 `v1.0.0`。
- **只读明细折叠**：逐项 handler 状态默认收起，`ours < total` 时自动展开（用户此刻正需要
  知道哪一项没成）。
- **低频项折叠而不是删除**：WinRAR、组件更新、提示音、跳过系统文件、排障入口放进
  「高级与排障」；能力不减，首屏不变长。
- **分区按使用频率排序**：外观 → 压缩默认值 → 引擎 → 打开方式 → Finder 集成。

## 7. 交互与状态

- 所有可点元素：hover 有背景反馈、按压有 scale、键盘有 `:focus-visible` 环
  （2px accent，offset 2px）——鼠标用户看不到，键盘用户一定看得到。
- 危险操作（删除、取消任务）用错误色 + 明确动词，菜单里危险项整项染色。
- 加载态用行内骨架/进度条，不做全屏 spinner。
- 空状态必须**给一个明确动作**（例：任务页空态 →「去压缩文件…」）。
- 错误就地显示在动作旁边（行内 hint / toast），不用模态框打断。
- **说明文字紧贴它的控件**（10px），不要推到行尾对齐：几十像素的空白会把说明读成
  独立的一列，归属变弱——和"入口挂在别人说明后面"是同一类错误。
- **一个控件只有一个提示通道**。行内状态行（`.opt-hint`）只表达**当前状态**（估算、
  后果、单位），随参数更新；**解释性文字放可聚焦的展开器**（`?` + `aria-expanded` +
  `aria-controls`），不用 hover 换文——hover 对键盘/触控不可达，还会让整块回流。
- **toast 只用于结果与异常**（完成、失败、覆盖），不用于解释"这个选项是什么"：
  它 3 秒后消失、离操作点远、无法回看。错误 toast 额外带 `role="alert"`
  （容器是 polite，错误必须插队立即播报）。
- **分段控件的语义是 radiogroup**，不是 tablist——它从不切换面板。按钮
  `role="radio"` + `aria-checked`，roving tabindex（只有选中项在 Tab 序）；
  方向键 / Home / End 的键盘行为不变。pill 定位跟随 `aria-checked` 选中项。
- **列表行可聚焦、可键盘操作**：待压缩文件行与归档条目行 `tabindex="0"`，
  ↑↓ 移动焦点；文件列表 Delete 移除行（移除的只是列表项，焦点留在列表内）。
  危险键（Delete）的读屏描述必须写明不删除磁盘文件。
- 行内状态行加 `role="status" aria-live="polite"`，开关用 `aria-describedby` 指向它。
- **缺失的能力要挂在它自己的选项上**，不要挂在别的选项的说明后面。禁用控件既不能
  hover 也不能聚焦，`title` 事实上不可达；而把入口放在"当前所选格式"的说明之后，它会
  跟着说明一起移动（同字号、同色、同间距），被读成那条说明的续句——归属错位比"看不见"更糟。
  做法：该选项用 `aria-disabled` + 标签内「需配置」，可聚焦可点击，点击不改变选择、
  直接落到那一行（展开折叠组、滚动、高亮 1.8s、把焦点交给可操作控件）；配置完成后
  回到原处立即生效（重画，不要求重启）。
- 说明槽只描述**当前选中项**。若某个选项永远无法被选中，它自己的说明要靠 hover/focus
  临时占用同一个槽位来显示（RAR 即如此），不要为此把说明写进别的选项的句子。
- **重建不等于重播**：数据没变就不要重建 DOM。分段控件的 pill 是独立元素，
  重建后它会从 `translateX(0)` 动画到目标位置（看起来像"自己滑了一下"），
  同时销毁焦点、让方向键连按失效。幂等重建 + 重建后 `instant` 落位（`.no-anim`）。
- **结束态不渲染活动进度条**：完成的任务不再保留满宽绿条贯穿卡片，状态由
  文字与图标承载；进行中的不确定进度必须明确"正在处理"，不伪造百分比。

## 8. 反模式（会被 audit 拦下）

| 反模式 | 替代 |
| --- | --- |
| `transition: all` | 列出具体属性 |
| UI 动画用 `ease-in` | `--ease-out` |
| 进入动画 `scale(0)` | `scale(0.955)` + `opacity: 0` |
| 交互反馈 > 300ms | 120–220ms |
| 纯黑 `#000` 文字 | 带色相的 `--ink` |
| 小字用 `--ink-4` 承载信息 | `--ink-3`（≥4.5:1） |
| 图标按钮只有 `title` | 加 `aria-label` |
| 卡片套卡片 / 什么都包卡片 | 分组用留白与分隔线 |
| 每个标题上一个圆角方块图标 | 图标只出现在有功能的位置 |
| 靠颜色区分状态 | 颜色 + 图标/文案 |
| hover 才能看到的说明 | 常驻短句 + 可聚焦展开器 |
| 每次渲染都重建控件 DOM | 数据签名不变就复用，只改属性 |

## 9. 检查方式

```bash
build/venv/bin/python scripts/design_audit.py          # 0 = 干净，2 = 有违规
build/venv/bin/python scripts/shots.py                 # 截图人工复核（检测通过≠好看）
```

`design_audit.py` 只覆盖可确定性判定的部分（对比度、缓动、时长、aria、焦点、
反模式字符串）。它通过不等于设计没问题——仍要在深浅两套、真实数据（超长文件名、
空列表、失败任务）下看一眼截图。
